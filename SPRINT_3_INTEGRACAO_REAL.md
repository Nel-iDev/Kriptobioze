# Sprint 3 — Integração Real

## Objetivo

Transformar o Kriptobioze em uma aplicação full-stack realmente integrada, onde o frontend consome a API REST do backend Spring Boot, que por sua vez consulta o PostgreSQL. Os três problemas críticos identificados na Sprint 2 foram corrigidos e novas interfaces foram criadas para funcionalidades que antes só existiam no backend.

## Problemas críticos corrigidos

| # | Problema | Solução | Arquivo |
|---|----------|---------|---------|
| 1 | `KB_API_BASE` não definido no HTML | Script tag ativa definindo `window.KB_API_BASE = "http://localhost:8080"` antes do app.js | `index.html:450` |
| 2 | Tabela `isotopes` não documentada no SQL | CREATE TABLE adicionado ao `01_schema.sql` + dados iniciais ao `02_dados_iniciais.sql` + entidade DER | `database/01_schema.sql`, `database/02_dados_iniciais.sql`, `database/DER.md` |

## Alterações no banco

### Tabela `isotopes` (nova no SQL)

```sql
CREATE TABLE IF NOT EXISTS isotopes (
    id                 BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name               VARCHAR(100)    NOT NULL,
    symbol             VARCHAR(20)     NOT NULL,
    half_life_years    DOUBLE PRECISION NOT NULL,
    description        TEXT,
    used_for           TEXT
);
```

Dados iniciais: 6 isótopos (C-14, U-235, U-238, K-40, Rb-87, Sm-147).

### Coerência SQL ↔ JPA ↔ DataSeeder

| Coluna SQL | Atributo Java | DataSeeder |
|------------|---------------|------------|
| `name` | `name` | `"Carbono-14"` |
| `symbol` | `symbol` | `"C-14"` |
| `half_life_years` | `halfLifeYears` | `5730.0` |
| `description` | `description` | `"Isótopo radioativo..."` |
| `used_for` | `usedFor` | `"Datação de fósseis..."` |

## Fluxos validados

### Fluxo principal (usuário → PostgreSQL → interface)

```
Usuário
↓
Frontend (index.html + app.js)
↓ fetch()
Spring Boot (Controllers)
↓ injeção de dependência
Services (lógica de negócio)
↓ chamada ao repositório
Repositories (JPA)
↓ JPA/Hibernate
PostgreSQL (tabelas: camada, fossil, isotopes)
↓ JSON
Frontend (renderização)
↓
Interface atualizada
```

### Fluxo de decaimento radioativo

```
Usuário seleciona isótopo + ajusta slider
↓
JavaScript calcula localmente (fallback)
↓
Usuário clica "Validar via API"
↓
KB.validateDecay() → POST /api/radioactive-decay/calculate
↓
RadioactiveDecayController → RadioactiveDecayService
↓
IsotopeRepository → PostgreSQL (tabela isotopes)
↓
JSON: { remainingFraction, halfLivesElapsed, checkpoints }
↓
Badge #apiDecayBadge atualizado
```

### Fluxo de Darwin

```
Usuário informa altitude e taxa
↓
KB.calculateDarwinUI() → POST /api/darwin/calculate
↓
DarwinController → DarwinCalculationService
↓
JSON: { yearsRequired, millionsOfYears, classification }
↓
#darwinResult atualizado
```

### Fluxo CRUD de fósseis

```
Usuário preenche formulário → clica "Criar"
↓
KB.createFossil() → POST /api/fossils
↓
FossilController → FossilService → FossilRepository.save()
↓
PostgreSQL INSERT
↓
Fossil retornado via JSON
↓
Tabela de fósseis recarregada (loadFossils())
```
